# AGENTS.md

Orientation for AI coding agents (and people) working in this repository. Read `README.md` first for the
science; this file says where things are, what must not change, and how to check your work.

## What this repository is

The inputs, analysis code, reduced data and figures of one NEMD study: heat flow across graphene /
n-perfluorohexane (C6F14) interfaces at 50, 100, 200, 250, 300, 350 and 400 bar, run with LAMMPS on ARCHER2 in
2025. The raw trajectories are not here. Everything that can be recomputed from the shipped data is checked by
one command:

```
python3 tools/verify_results.py            # exit 0 = all checks pass
python3 tools/verify_results.py --write    # also rewrites data/summary.json
```

## Rules

1. **Do not edit `simulation/as_run/`, `data/` or `figures/`.** They are records of what was run and produced.
   The exceptions are `data/summary.json`, generated by `tools/verify_results.py --write`, and `data/README.md`,
   which documents the columns and units (two data headers carry wrong units; the files are left as produced).
2. **Do not change the shipped analysis scripts to "fix" them.** Their known issues are listed in `README.md`
   ("Known issues in the shipped code") and are kept so that the code matches the published numbers. Put
   corrected versions in a new file and say what changes.
3. **Every number in `README.md` must trace to a file in `data/`** and pass `tools/verify_results.py`. If you
   add a number to the README, add a check for it.
4. **Do not invent provenance.** If something cannot be established from the files (for example, achieved
   pressure during the heat-flow run, or energy drift), say so.

## Facts that are easy to get wrong

| Fact | Value | Where it comes from |
|---|---|---|
| Atoms in the simulated system | 44,800 (two copies of the 22,400-atom step-0 cell) | `simulation/template/step3_nve/in.run` (two `read_data ... add append`) |
| PFH molecules | 800 (400 per slab), 20 atoms each | `simulation/initial_config/combined_system.dat` |
| Graphene sheets | 36 of 800 atoms: four 9-sheet walls, paired into two 18-sheet stacks | `simulation/template/step5_dump/in.groups` (diagram) |
| Graphene/PFH interfaces | 4; heat takes two parallel paths, each crossing 2 | same |
| Thermostatted sheets | atom types 4 to 6 and 13 to 15; 6 sheets at 350 K, 6 at 250 K | `simulation/template/step4_therm/in.groups`, `in.varDefs` |
| Cross-section | 2150 Å² (2152 Å² at 100 bar; not the 2096 Å² of the step-0 box) | implied by `data/heat_flux_J.dat`; checked by `verify_results.py` |
| J | the thermostat energy is averaged as (E_cold - E_hot)/2 (column 3 minus column 2 of `out.<P>_bar`, halved), fitted against time after 5 ns; half that slope (two paths) over the cross-section | `analysis/step1_heat_flux/compute_heat_flux.py` |
| Where the temperature jump is measured | at the contact graphene sheet's position, from a linear fit to the central 100 of 250 PFH bins | `analysis/step5_calc_Rk/comp.Rk.block.py` |
| R_K reported | mean of hot and cold interfaces (about 341 K and 259 K); hot is 13 to 24 % lower, depending on pressure | same |
| Error bars | population sd (ddof = 0) of 5 consecutive 4 ns blocks of one run; not a standard error | `analysis/step5_calc_Rk/plot.final.py` |
| Units | R_K m² K/W (the `data/Rk_pfh.dat` header is wrong); J W/m²; thermostat energy eV; spectra eV ps⁻¹ Hz⁻¹ | |
| 100 bar | separate earlier batch; differences listed in README | `simulation/as_run/pressure_100bar/` |

## Data files and their columns

| File | Columns |
|---|---|
| `data/Rk_pfh.dat` | pressure (bar), R_K mean (m² K/W), R_K sd (m² K/W) |
| `data/heat_flux_J.dat` | pressure (bar), R² of the linear fit, power per path (eV/ps), J (W/m²) |
| `data/density_stats.dat` | pressure, bulk density (kg/m³), first-peak density at the hot interface (kg/m³), peak distance from the sheet (Å), ratio |
| `data/heat_flux_qInOut/out.<P>_bar` | timestep, cumulative energy of the hot thermostat (eV, negative = added), of the cold thermostat (eV); every 1e4 steps |
| `data/per_pressure/<P>bar_hot_sheets.dat`, `_cool_sheets.dat` | sheet index, mean position (Å), position error (population sd of the 5 block-mean positions), temperature in blocks 1 to 5 (K); data rows 1 to 9 right domain, 10 to 18 left domain (the index column restarts at 1); data rows 9 and 18 are the sheets touching the PFH; positions are given for the right domain only, mirrored for the left |
| `data/per_pressure/<P>bar_pfh_temp.dat` | bin position (Å), temperature in blocks 1 to 5 (K); 250 rows right slab, then 250 left; the left rows reuse the right slab's position grid (the slabs are averaged as mirror images) |
| `data/per_pressure/<P>bar_pfh_dens.dat` | bin position (Å), density in blocks 1 to 5 (kg/m³); 5000 rows right slab, then 5000 left, on the right slab's position grid |
| `data/per_pressure/<P>bar_kapitza_stats.dat` | block, R² of the fits (hot, cold, PFH), PFH thermal conductivity (W/m K), jump hot, jump cold (K), R_K hot, cold, mean (m² K/W) |
| `data/spectral_heat_flux/<P>bar_fluid.dat`, `_solid.dat` | frequency (Hz), spectral heat flux x, y, z, total (eV ps⁻¹ Hz⁻¹; the header says eV/s); solid side has the opposite sign |
| `data/sheet_positions/positions_means.dat` | pressure, mean z of the left-cold, left-hot, right-hot and right-cold contact sheets (Å) |
| `data/summary.json` | the main results per pressure (not the block values, profiles or spectra), with units, written by `tools/verify_results.py --write` |

## Running the shipped scripts

Only the last stage of the analysis runs from `data/`: in `analysis/step5_calc_Rk`, `comp.Rk.block.py`,
`comp.Rk.py`, `cmp.Rk_graphene_pfh.py`, `plot.final.py` and `comp.peak_bulk_dens.py` read `outs/`; in
`analysis/step6_sdhf`, the `plot.sdhf_*.py` scripts read `sdhf_consolidated/` and `../step1_heat_flux/output.dat`.
The other step-5 scripts (`comp.sheet_temp.py`, `comp.pfh_temp.py`, `comp.pfh_dens.py`) read the per-dump
outputs of analysis steps 2 to 4 in sibling folders, which come from the trajectories and are not here.
`tools/verify_results.py` shows how to stage copies in a temporary folder; do that rather than writing into
`analysis/`. The step-5 scripts start with an ARCHER2 Python path; call every script as `python3 -I script.py`.

The spectral heat flux covers the two hot-wall interfaces only: the production dumps tally graphene-PFH forces
for the hot walls (`lhotwall`, `rhotwall`) and not for the cold ones.
